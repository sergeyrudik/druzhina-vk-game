Ответственный за релиз отмечает пункты только после проверки production-сборки
внутри VK. Если обязательный пункт не выполнен, релиз не отправляется на

- [ ] В рабочей ветке нет случайных файлов, токенов и секретов.
- [ ] Установлена поддерживаемая версия Node.js.
- [ ] `pnpm install --frozen-lockfile` проходит с чистого окружения.
- [ ] `pnpm run typecheck` проходит без ошибок.
- [ ] `pnpm run lint` проходит без ошибок.
- [ ] `pnpm test` запускает все 22 теста: 20 проверок игрового движка и 2
  проверки production export.
- [ ] Все 22 теста завершены успешно, без неожиданных `skip` и `todo`.
- [ ] `pnpm run test:all` проходит без ошибок.
- [ ] `pnpm run timeweb:build` создаёт `out/index.html`.
- [ ] Созданы `out/privacy/index.html` и `out/terms/index.html`.
- [ ] В консоли браузера нет необработанных ошибок.
- [ ] В production не загружаются скрипты или шрифты с заблокированных в РФ CDN.
- [ ] В клиентскую сборку не попали секретный ключ VK и служебные токены.

## 2. Основной игровой сценарий — обязательно

- [ ] Новая игра начинается с понятного первого действия.
- [ ] Объединяются только одинаковые бойцы одного уровня.
- [ ] Найм корректно списывает монеты и не переполняет лагерь.
- [ ] Кнопка боя не запускает две волны одновременно.
- [ ] Урон, здоровье города и победа в волне рассчитываются корректно.
- [ ] Ратник получает преимущество возле стен.
- [ ] Лучник начинает атаковать раньше бойцов ближнего боя.
- [ ] Волхв наносит урон по площади второму противнику.
- [ ] Страж уменьшает урон прорвавшихся врагов по стенам.
- [ ] Карточка выбранного бойца показывает его силу и роль.
- [ ] Подсказка пары выбирает реально объединяемых бойцов или честно сообщает,
  что пары нет.
- [ ] На 5-й и 10-й волнах каждой главы появляется босс.
- [ ] Поражение сохраняет дружину, ресурсы, улучшения, главу и номер волны.
- [ ] После поражения стены восстанавливаются до 65%, и повторяется текущая
  волна, а не весь поход.
- [ ] Повтор волны не дублирует добычу незавершённой попытки.
- [ ] Победа показывает название следующей главы и понятный следующий шаг.
- [ ] Последовательно проверены все пять глав: «Берёзовый тракт», «Волчья
  пуща», «Каменный перевал», «Туманные болота», «Северная застава».
- [ ] После пятой главы начинается новый круг, сложность остаётся конечной и
  проходимой.
- [ ] Прогресс сохраняется после обновления страницы.
- [ ] Более новое сохранение не перезаписывается старым.
- [ ] Сброс прогресса действительно создаёт новую игру.
- [ ] Сворачивание приложения не продолжает бой неконтролируемо.

## 3. VK Bridge и отказоустойчивость — обязательно

- [ ] `VKWebAppInit` успешно выполняется внутри VK.
- [ ] Отказ `VKWebAppGetUserInfo` не блокирует интерфейс.
- [ ] VK Storage проверен на одном аккаунте на двух устройствах.
- [ ] Недоступность VK Storage оставляет рабочее локальное сохранение.
- [ ] Запуск по прямой ссылке не приводит к белому экрану.
- [ ] Все ошибки Bridge обрабатываются без `unhandled promise rejection`.
- [ ] Смена размера iframe не обрезает ключевые кнопки.

## 4. Реклама — обязательно при включённой монетизации

- [ ] Перед предложением rewarded выполнена проверка доступности рекламы.
- [ ] Пользователь видит размер награды до запуска рекламы.
- [ ] Rewarded запускается только по явному нажатию пользователя.
- [ ] Награда начисляется один раз и только после успешного просмотра.
- [ ] При закрытии или ошибке награда не начисляется.
- [ ] После ошибки можно продолжить игру без рекламы.
- [ ] После успешной rewarded-рекламы включается cooldown 3 минуты.
- [ ] Во время cooldown кнопка недоступна и показывает оставшееся время.
- [ ] После восьмой rewarded-награды за календарный день включается дневной
  лимит.
- [ ] Cooldown, дата и дневной счётчик сохраняются после перезагрузки.
- [ ] На следующий календарный день дневной счётчик начинает новый лимит.
- [ ] Interstitial показывается только в естественном переходе между волнами.
- [ ] Interstitial не показывается в обучении, во время боя и сразу после поражения.
- [ ] Первый interstitial не показывается раньше трёх минут после начала сессии.
- [ ] Между interstitial-показами проходит не меньше трёх минут.
- [ ] Зафиксированы события предложения, старта, успеха и ошибки рекламы.
- [ ] Тестовые рекламные настройки заменены production-настройками.

## 5. Аналитика и продуктовые события

- [ ] Фиксируются `app_open` и `game_start`.
- [ ] Фиксируются первое объединение и завершение обучения.
- [ ] Фиксируются начало, победа и поражение каждой волны.
- [ ] Фиксируются найм, лечение и расход валюты.
- [ ] Фиксируются завершение и повторный запуск кампании.
- [ ] Ошибки рекламы и сохранения отделены от продуктовых событий.
- [ ] В события не передаются имя, фамилия, токены и другие лишние персональные данные.
- [ ] События проверены в панели аналитики на тестовом аккаунте.

## 6. Интерфейс и доступность — обязательно

- [ ] Нет кнопок, которые выглядят активными, но ничего не делают.
- [ ] У всех интерактивных элементов понятные подписи.
- [ ] В viewport `320×568` нет горизонтального скролла; шапка, ресурсы и кнопки
  не перекрывают друг друга даже при загруженном профиле VK.
- [ ] В viewport `320×568` стартовый экран и модальные окна прокручиваются,
  основное действие и кнопка закрытия достижимы.
- [ ] В viewport `320×568` нижняя навигация остаётся доступной и не перекрывает
  игровое действие или последний элемент страницы.
- [ ] В viewport `390×844` корректно учитываются safe-area; карточки лагеря,
  заданий и итогов не выходят за экран.
- [ ] В viewport `390×844` все 12 ячеек дружины и их уровни читаются, зоны
  касания не меньше 44×44 px.
- [ ] В desktop viewport `1000×700` нет горизонтального скролла, а шапка,
  игровой блок и навигация не перекрывают друг друга.
- [ ] В `1000×700` с клавиатуры достижимы все основные действия; видимый
  `focus-visible` не обрезается контейнерами.
- [ ] Текст не выходит за границы карточек при системном увеличении масштаба.
- [ ] Состояния `disabled`, загрузки и ошибки визуально различимы.
- [ ] Для анимаций учитывается `prefers-reduced-motion`.
- [ ] Основные действия доступны с клавиатуры.
- [ ] Открытый dialog удерживает фокус, закрывается клавишей Escape и возвращает
  фокус на вызвавшую его кнопку.
- [ ] Активный раздел навигации передаётся не только цветом, но и
  `aria-current`.
- [ ] Динамическое сообщение озвучивается screen reader один раз.
- [ ] Цвет — не единственный способ показать важное состояние.
- [ ] Звук можно выключить; настройка сохраняется.
